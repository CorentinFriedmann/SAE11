# 3. Choix et justifications : le pourquoi

| Question | Notre choix | Écarté | Pourquoi |
|---|---|---|---|
| Orchestrateur | **k3s** v1.35 | kubeadm, Docker Compose | Un binaire, 512 Mo de RAM ; Traefik, stockage local-path, metrics-server et NetworkPolicy (kube-router) fournis : rien à installer en plus sur une VM de 4 Go. Compose n'est accepté que comme étape. |
| Outil de déploiement | **Kustomize** (`kubectl apply -k`) + `deploy.sh` | Helm (O1) | Intégré à kubectl, manifestes lisibles tels quels. Le `configMapGenerator` ajoute un hachage au nom des ConfigMaps : toute modification de configuration redéploie BookStack. Helm apporterait le paramétrage multi-environnements, inutile pour une maquette. |
| Image BookStack | **lscr.io/linuxserver/bookstack:v26.09.2-ls296** | `solidnettech/bookstack`, image construite par nous | La plus suivie, publiée à chaque version, migrations de base automatiques au démarrage. Étiquette `vX-lsN` = build précis ; « version-vX » bouge à chaque rebuild. Contrepartie : démarre en root (s6) → Pod Security « baseline », pas « restricted » (partie 9). |
| Image MariaDB | **mariadb:11.8.9** (LTS) | MySQL 8, 12.x (rolling) | Image officielle, LTS jusqu'en 2028, `healthcheck.sh` intégré pour les sondes. |
| MariaDB : objet | **StatefulSet** (1 réplica) + Service headless | Deployment + PVC | Identité stable `mariadb-0`, PVC créé par `volumeClaimTemplates` et **conservé si la StatefulSet est supprimée**, jamais deux pods sur le même volume (un pod est recréé seulement après la fin du précédent). À un seul réplica, l'écart avec un Deployment Recreate est faible ; la StatefulSet protège mieux la donnée et prépare une réplication. |
| BookStack : objet | **Deployment, Recreate** | RollingUpdate, StatefulSet | Application sans état propre hors `/config`. RollingUpdate démarrerait le nouveau pod avant d'arrêter l'ancien : deux pods sur un volume RWO et deux migrations de schéma concurrentes. Recreate coûte ~15 s de coupure à chaque mise à jour (mesuré). |
| Stockage | **local-path** (PVC RWO) | NFS, Longhorn | Fourni par k3s, performances du disque local. Longhorn demande ~1 Go de RAM par nœud et trois nœuds ; NFS un serveur de plus. Le prix : volume lié au nœud (partie 5). |
| Exposition | **Ingress Traefik** + TLSOption + Middlewares | NodePort, ingress-nginx | Traefik est déjà le contrôleur de k3s. Pas de limite de taille de corps par défaut (pièces de 20 Mo). |
| Certificat | **Autorité interne** générée par `gen-secrets.sh` (ECDSA P-256, CA 10 ans, serveur 397 j) | Let's Encrypt, certificat auto-signé seul, cert-manager (O6) | ACME (RFC 8555) exige un nom public : impossible en `.lab`. Un certificat auto-signé seul ne s'importe pas proprement ; une autorité (RFC 5280) se distribue une fois aux postes et signe les certificats suivants. cert-manager automatiserait le renouvellement (partie 9). |
| Secrets | **Secret Kubernetes** créé par script depuis `.secrets/` (ignoré par Git) | Sealed Secrets, SOPS, Vault | Aucun outil de plus ; `secret.exemple.yaml` documente la forme. En production : chiffrement au repos d'etcd et SOPS/Sealed Secrets pour versionner chiffré. |
| Sauvegarde | **CronJob** `mariadb-dump --single-transaction` + `tar` de `/config`, rétention 7 j, **export hors cluster** | Velero, instantané du volume | Dump logique cohérent sans arrêt (InnoDB, MVCC), restaurable sur une autre version de MariaDB ; lisible et vérifiable (sha256). Velero : plus complet mais demande un stockage objet (A2). |
| Cloisonnement des prestataires | **Rôle Prestataire sans aucune permission de rôle** + **un rôle « Accès client – X » par client**, permissions posées **livre par livre** | Un rôle par sous-traitant ; permissions par étagère seule | Les permissions d'étagère de BookStack **ne descendent pas** aux livres : on les pose sur chaque livre. Un rôle par client suit l'énoncé (« fiches des clients qui **lui** sont attribués ») : deux techniciens d'un même sous-traitant peuvent avoir des clients différents. Par défaut un prestataire ne voit rien ; tout accès est une ouverture explicite. |
| Double authentification | **TOTP natif de BookStack**, « MFA obligatoire » par rôle | OIDC/Keycloak avec MFA (O2) | Natif, aucun composant de plus ; obligatoire pour Administrateur, Prestataire et rôles d'accès client. |
| Désactivation d'un compte | **`disable-user.sh`** (rôles retirés, mot de passe aléatoire, MFA et sessions supprimés, nom préfixé) | suppression du compte | BookStack n'a pas d'interrupteur « désactivé ». Supprimer le compte casserait la lisibilité du journal d'audit ; on le neutralise et on le garde. `SESSION_DRIVER=database` permet de couper ses sessions ouvertes. |
| Configuration de BookStack | **Script d'API idempotent** (`init-bookstack.sh`) | clics dans l'interface | Reproductible (R10), relu en revue de code, rejouable. Le jeton d'API est créé en base pour la durée du script puis supprimé. |
